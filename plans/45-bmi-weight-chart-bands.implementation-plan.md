# 45. BMI-полосы на графике веса (парный план, бэк)

Основной план — фронт: `megaapp-front/plans/45-bmi-weight-chart-bands.implementation-plan.md` (общий модуль категорий BMI, плагин графика, переключатель). Здесь только то, что делает бэк. Номер, имя и коммиты `[045]` общие для обоих репозиториев.

## Цель

Сервер хранит и отдаёт пользовательский флаг «показывать BMI-полосы на графике веса».

## Текущая архитектура

- Настройки сгруппированы по пространствам; food-пространство хранит рост, диапазон дат, метрику топа продуктов и раскрытые блоки статистики.
- Хранится как JSON-документ на пользователя и пространство. Миграции БД для нового поля не нужны.
- Запись принимает только объявленные поля: неизвестное имя поля отклоняется, `null` допустим лишь для полей-указателей.
- При чтении сохранённый документ накладывается на дефолты пространства, поэтому поле, которое пользователь ни разу не сохранял, возвращается со значением по умолчанию.

## Решение

- В food-настройки добавляется булево поле флага полос. Дефолт — включено.
- Дефолт задаётся в дефолтах food-пространства, а не нулевым значением типа: у существующих пользователей документ без поля, и они должны получить включённое состояние.
- Булево не указатель: `null` для него отклоняется, как для остальных булевых настроек.
- Других изменений нет: маршруты, права, рассылка обновлений и идемпотентность общие для всех полей.

## Ограничения

- Деплой бэка раньше фронта: пока поля нет, строгий разбор отклоняет запись флага.
- Фронт без поля в ответе подмешивает свой дефолт, так что порядок «фронт раньше» не ломает чтение, только сохранение.

## Тесты

- Дефолт при чтении без сохранённого документа: флаг включён.
- Запись выключенного состояния и чтение обратно.
- Существующий документ без поля читается с флагом по умолчанию.
- `null` для флага отклоняется.
