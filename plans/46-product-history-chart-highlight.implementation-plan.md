# Выделение выбранных продуктов на графике калорий — бэкенд (парный план)

Основной план: [46-product-history-chart-highlight.implementation-plan.md](../../megaapp-front/plans/46-product-history-chart-highlight.implementation-plan.md).

## Описание

Фронт делит столбик калорий дня на выбранные продукты истории (план [31](31-food-product-history.implementation-plan.md)) и остальное. Для этого запись истории должна нести калории события.

## Решение

- Запись истории получает `kcal` — калории события по персональному значению на 100 г за месяц самого события (то же значение, из которого уже считался процент от нормы; целое, как `consumedKcal` дневника по записям).
- `percentOfNorm` остаётся: таблица истории показывает его для любых дней, в том числе старше окна статистики, где нормы дня на фронте нет.
- Прежнее решение «ккал в ответ не отдаём» (план 31) отменено: появился потребитель. Раньше это была промежуточная величина.
- Изменение обратно совместимо (поле добавлено) — выкладывать бэк раньше фронта.
- Эндпоинт, контракт запроса, индекс и отсутствие кэша — без изменений.

## Чеклист

- ✅ Тесты: сервис (ккал и % на тех же событиях), HTTP-ответ содержит `kcal` вместо прежней проверки его отсутствия
- ✅ `go build ./...`, `go vet ./...`, `go test ./...` — зелёно
- ⭕ Выкладка бэка раньше фронта
